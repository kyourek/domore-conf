## Summary

The branch adds a public `Conf.Contain(object source, string special, string comment)`
overload and makes `Contain(object, string)` forward to it with the global `Conf.Comment`.
The forwarding preserves existing behavior: the two-argument overload still creates a
`ConfContainer` with `Source`, `Special`, and `Comment = Conf.Comment`, exactly as the
baseline did. Existing callers are unaffected at the source and binary level because the
original overloads remain.

One confirmed finding: P3 x1 (resolved).

## Findings

### #1 [P3] New `comment` parameter has no test coverage; a miswiring would go undetected [Resolved]

- Status: Resolved
- Location: `source/Domore.Conf/Conf/Conf.cs:128-134` (target revision)
- Problem and trigger: The new overload's only new behavior is assigning its `comment`
  argument to the created container (`Comment = comment`, line 132). No test calls the
  three-argument overload or checks that a per-call marker differs from the global
  `Conf.Comment`.
- Impact: If the assignment reverts to `Comment = Comment`, the exact baseline line, it still
  compiles. The unqualified `Comment` then resolves to the static `Conf.Comment` property, so
  the overload would silently ignore its argument and all existing tests would still pass.
  The repository guidance (`AGENTS.md`, "Tests") asks for coverage of behavior changes.
- Evidence: Static trace. Before this change, line 121 read `Comment = Comment` and the
  full `Domore.Conf.Tests` suite passed. A search of `tests/` finds no three-argument
  `Conf.Contain` call. The comment tests in `tests/Domore.Conf.Tests/Conf/ConfContainerTest.cs:1304-1435`
  construct `ConfContainer` directly and never go through `Conf.Contain`.
- Suggested resolution: Add tests in `tests/Domore.Conf.Tests/Conf/ConfTest.cs`, marked
  `NonParallelizable` wherever they change the global `Conf.Comment`. Cover these cases:
  (a) `Conf.Contain(source, "@conf", "//")` ignores `// Text = ignored` lines while
  `Conf.Comment` is null; (b) `Conf.Contain(source, "@conf", null)` keeps comments
  disabled when `Conf.Comment` is set to a marker that would otherwise hide a line;
  (c) `Conf.Contain(source, special)` still inherits `Conf.Comment`.
- Verification: The new tests pass on the target. They fail if line 132 is changed back to
  `Comment = Comment`.

Resolution: Added two `NonParallelizable` tests to `tests/Domore.Conf.Tests/Conf/ConfTest.cs`.
`ContainWithCommentEnablesCommentsWhenGlobalCommentIsNull` (lines 173-186) covers case (a).
It sets `Conf.Comment` to null, calls `Conf.Contain(source, "@conf", "//")`, and asserts that
the `//` line is not parsed as a pair (`Lookup.Count == 1`) and that `C.Text` binds to
`expected`. `ContainWithNullCommentDisablesCommentsWhenGlobalCommentIsSet` (lines 188-200)
covers case (b). It sets `Conf.Comment = "C.Text"`, calls `Conf.Contain(source, "@conf", null)`,
and asserts that `C.Text` still binds. Case (c) was already covered by
`CommentIsUsedByStaticMethodsAndNewContainers` (`ConfTest.cs:165`), so no test was added for
it. The production code was not changed.

Verification:
- Red: `Conf.cs:132` was temporarily changed back to `Comment = Comment`, then
  `dotnet test tests/Domore.Conf.Tests --configuration Release --framework net10.0 --filter
  "FullyQualifiedName~Domore.Conf.ConfTest"` was run. Both new tests failed for the expected
  reasons: "Expected: 1 But was: 2", where the comment line was parsed as a pair, and
  "Expected: "expected" But was: null", where the global marker hid the line. The temporary
  change was then reverted.
- Green: `dotnet test tests/Domore.Conf.Tests --configuration Release` passed on net462,
  net47, net471, net472, net48, and net481 (391 passed, 14 skipped each) and on net8.0 and
  net10.0 (405 passed).
- Limitation: net9.0 was not run because the .NET 9 runtime is not installed on this
  machine.

## Optional improvements (not defects)

- `source/Domore.Conf/README.md:58-74` says comments are enabled only through the global
  `Conf.Comment`. Line 56 documents `Conf.Contain(source, special)` for the directive prefix.
  A matching sentence for `Conf.Contain(source, special, comment)` would make the
  per-container option discoverable.
- The `<param name="comment">` text at `source/Domore.Conf/Conf/Conf.cs:126` leaves out the
  semantics documented on `Conf.Comment` (`Conf.cs:50-54`): null, empty, or whitespace
  disables comments, and matching is case-sensitive. A short `<remarks>` or a `<see cref>`
  to `Comment` would keep the contracts aligned.
- The public API addition is intentional (commit subject "Add an overload for Contain.").
  This review did not treat it as an unrequested API change.
